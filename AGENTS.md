## Jackboy rules
- Post-merge readiness compares live workflow blob, configured policy and database pins read-only; historical OMNI sessions never prove current bridge reachability.
- Activation checklist separates timestamped live safety reads from dated integration observations; local tests and historical snapshots never grant production readiness.
- Add project to CODE (`code-onboarding*.ts`, `CodeSiteCard.tsx`, profiles in `src/lib/code-profiles/`): prepare writes only the exact approved profile files to `jackboy/code-onboarding` and opens a draft PR; a site is usable only where its passkey-pinned DB entry (owner-only `set_code_site_pin`, fresh `code_site_pin` grant bound to repo+SHA) and `CODE_TARGETS` agree on main and the live workflow blob; the Jackboy anchor pin is never changed by this flow.
- CODE approval lanes (`code-lane.ts` rules, `code-lane.server.ts`, `CodeLanePanel.tsx`, staged `staging/code-lane/`): the server picks the lane before dispatch and stores it on the request; runner claims must present the matching environment identity (`CODE`/`CODE-PUBLISH` reviewed, `CODE-AUTO`/`CODE-PUBLISH-AUTO` automatic), automatic runs also need the passkey-set per-site switch and a server re-check of the reported patch; anything else is reviewed and merging always stays with the owner.
- Reports, phone alerts and Undo (`daily-report*.ts`, `owner-alerts*.ts`, `code-undo*.ts`, `/reports`, cron `/api/public/jobs/owner-alerts`): built only from real records and read-only except Undo; alerts are deduplicated outbox rows that only link to on-site pages (never approve), marked sent only when a device accepted them; push uses Firebase project jackboy-b6bb5 (public web config + GOOGLE_API_KEY/FIREBASE_VAPID_KEY served to the owner, sending via the firebase_messaging connector); Undo closes unmerged draft PRs, and for merged changes needs a fresh `code_undo` passkey, refuses on file clashes and merges only its own revert after checks pass.
- CODE environment policy narrows the stored workflow allowlist; missing or mismatched policy fails closed. Readiness probes never dispatch, and activation stays locked until storage, spend enforcement and runner isolation pass.
- New generated work prioritizes product fixes/features; test-only proposals require a named verified feature blocker. Draft PR creation is gated by passing checks for its changed commit, not static validation alone. Shared chat tools supply validated evidence links; credit failures pause paid work without inference probes or invented balance APIs.
- Per-project permission refresh stores live read results and provider-declared write grants separately for GITHUB_TOKEN and the actual App work credential; never prove write by launching jobs or auto-resuming work. Passkey removal atomically consumes an owner/device-scoped grant and invalidates unused grants from that credential.
- Repository drift and missing-link matches are read-only evidence from GITHUB_TOKEN inventory; unified owner/passkey approval atomically updates current repo/profile/inventory names, validates profile snapshots, preserves immutable history and blocks running/approval-bound targets so resync cannot redirect existing work.
- Owner identity configuration and mail delivery are separate states; auth helpers revalidate confirmed sign-in and propagate sender failures, so configuration gaps never become fake email success or owner access.
- All private pages live under `src/routes/_authenticated/` (client gate checks session + `my_role`, else `/onboarding`); server functions and RLS re-check roles. Owner bootstrap only via `claimOwner` matching the `OWNER_EMAIL` secret; others join only via `accept_invitation` RPC (email match). Roles live in `user_roles`.
- Internet research is server-only (`src/lib/research.functions.ts`, policy in `src/lib/search-policy.ts`): Brave key in `BRAVE_SEARCH_API_KEY` secret, domain allowlist, timeout, audit-log-based rate limits; never return fake results when unconfigured.
- Lovable Cloud is enabled for account infrastructure; existing browser-local demo stores remain demo-only until an explicit user-scoped storage migration, so enabling auth never makes old demo records shared private data.
- Layout/code changes are only proposed as suggestions and applied via `resolveSuggestion` after explicit approval, which writes to the log.
- Autonomous Activation lives in one panel (`ActivationPanel.tsx`, order in `src/lib/activation-steps.ts`) at the top of Settings, holding three independent controls (system Kill Switch, saved CODE setting, CODE Emergency Stop; view rules in `src/lib/safety-controls.ts`, live read `getSafetyControlState`) and guided steps. Each control has its own saved setting, owner-only audited action and passkey (`set_automation_policy`; `setCodeEnabled`→`set_code_enabled`; `engageCodeKillSwitch`/`releaseCodeEmergencyStop`) and never writes the other two; CODE runs only when the Kill Switch is off, the stop is released, CODE is saved ON and every gate passes, enforced at every CODE start/AI call in the database and in `codeStartBlockReason`. The database side is migration `0065_code_independent_controls`; the app still checks `code_independent_controls_installed()` and, if it is ever false or unreadable, the Kill Switch also engages the CODE stop and the on/off/release actions lock, so nothing is less safe. Steps never auto-press, and the stop controls stay visible after the steps fold away. Home shows status plus a link only. Readiness checks (`src/lib/readiness*.ts`) are read-only Tests logged to `site_log` (`readiness.test`) combined with live observations; newest evidence wins and missing evidence is NOT TESTED.
- Global Kill Switch (`automation_policy.paused`) is enforced server-side through `global-pause.server.ts` (rule in `global-pause.ts`, fail closed) at every work entry point (inspect, Foundry execute/tick, Autopilot writeFix/tick, update writer run/deliver, AutoConnect tick, Task Mode); read-only reporting keeps running. Settings → "What's really running" (`autonomy-status*.ts`, `AutonomyStatusPanel.tsx`) compares switches with run records (job heartbeats/last-tick times) and keeps GitHub CODE gates separate; a switch alone never counts as running.
- Shared shell is `src/components/AppShell.tsx` (from `__root.tsx`); main menu stays small (Home, Projects, Connect, Approvals, Chat, Settings) and every advanced page is listed on `/settings` so menus never duplicate.
- The Connect picker lists only stored inventory (`agent_projects.lovable_project_ref`) labelled as a snapshot; live Lovable discovery appears only after a real linked, tested connection.
- Jackboy is the research/evaluation/idea-routing agent; OMNI is the build/test/deploy engine. Handoffs, monetization estimates and provenance live in `src/lib/omni-handoff.ts` + `src/routes/omni.tsx`; publish/pricing/sell stay locked by `canApprove` until the handoff is approved and provenance is cleared. Never show OMNI as connected without verification.

- OMNI execution permits (`omni-permit.ts` rules, `omni-permit.server.ts` on the `omni.link/v2` endpoint, `omni-autonomy.functions.ts`, `OmniAutonomyPanel` on `/omni`, staged `scripts/omni-execution-permit-draft.sql`, contract `docs/OMNI-PERMIT-CONTRACT.md`): Jackboy is the final gate for OMNI autonomous/CODE work; OMNI needs a session-signed permit (≤60 s, renewed) re-checked against Kill Switch, Emergency Stop, CODE setting and a fresh-passkey owner authorization; stopping revokes permits in the same transaction and never fails the stop; missing service fails closed.
- Subdirectories have their own `AGENTS.md` (feature rules in `src/lib/AGENTS.md`); read it before changing files there.
- Frontend conversation forks copy historical text/files without executable tools or grants; retries restore unsent drafts because the chat transport can perform external side effects and has no enforced tool-free regeneration mode.
- Live voice runs through `src/lib/live-relay.server.ts` at `/api/live` (dispatched in `src/server.ts`, dev via `live-vite-plugin.ts`): owner session verified before any paid voice session, and legacy voice change tools stay blocked; opt-in CODE requests use scoped session-bound cards, while sensitive actions keep their passkey/provider-native path.
- Repo inventory = GITHUB_TOKEN repos + live GitHub App installation repos; per-project resync (`project-resync.functions.ts`) may change only display name/empty site address, repo-link changes stay in the approved review, and gone projects are archived (`active=false`), never deleted.
- OMNI self-test remote runner (`omni-remote-runner*.ts`, `/api/public/omni/runner`): the live site keeps all link checks and storage; the Railway runner-only host is stateless (no DB, no link secrets), runs only the fixed self-test over signed, nonce-bound requests, and any runner error fails the job, never passes it. `runnerModeDecision` ignores `OMNI_LINK_RUNNER_MODE` on Lovable/local hosts or when site-only settings exist, so a misplaced runner setting can't blank the dashboard.
- Site monitoring lives in `src/lib/site-monitor*.ts` (DNS-over-HTTPS + one HTTPS GET, stored on owner_projects with backoff, 15-min cron at /api/public/jobs/site-monitor); reachability never implies coding access.

- Autonomous Operating Guidelines (`src/lib/guidelines.ts`, `docs/AUTONOMOUS-GUIDELINES.md`) override any task: they are prepended to every AI work/chat prompt and enforced in branch/workflow guards and the two-failure stop.
- Deployed version is proven only by `/api/public/version` (git commit/tree/dirty stamped at build time in `vite.config.ts`, compared with GitHub main in readiness); a null commit or dirty build never counts as proven.
- Migrations recorded in production's journal keep their exact bytes and `when`; on a number clash renumber only unapplied entries and keep them newer than the latest applied row (guard: `tests/migration-history-reconcile.test.mjs`).
